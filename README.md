# SG-Share: Auditable Online Group Adaptation

This repository is a clean-room reconstruction and audit package for SG-Share,
an online group-adaptation system for passive-sensing mental-health streams. It
contains the stream preparation code, the current SG-Share learner, online and
offline comparison runners, grouping/component ablations, and provenance
records.

The historical experiment repository was not recovered byte-for-byte. Results
and claims are therefore separated into:

- **Recovered tuned-system results**: values recovered from experiment outputs
  and execution records.
- **Current reconstruction results**: values generated by the `sgshare/`
  implementation in this repository.
- **Expected manuscript values**: reference values stored under `expected/`;
  these are not silently presented as newly reproduced results.

Read [the provenance record](docs/PROVENANCE.md),
[reproduction status](docs/REPRODUCTION_STATUS.md), and
[SOTA audit](docs/SOTA_FAITHFULNESS_AUDIT.md) before interpreting numerical
comparisons.

## Implemented online protocol

All SG-Share runs are prequential: each event is predicted first, its label is
then revealed, and only past and current labeled feedback may be used for an
update.

The implemented group path is:

1. A temporary rank-4 LoRA adapter serves each user before group eligibility.
2. The classification-loss gradient on `route_w` updates a per-user EMA
   signature.
3. At a regroup boundary, eligible signatures are standardized and projected to
   at most eight principal coordinates.
4. Full regrouping starts from user singletons and repeatedly merges the pair of
   group centroids with maximum cosine similarity. It stops at `k_min` groups or
   when the best similarity is negative.
5. Stable group identifiers are matched to the new partition. Eligible users
   train and predict through their assigned group adapter; in the default
   `standalone` mode, their temporary personal adapter is not updated afterward.

For the tuned CES point used by the current runners:

```text
route-gradient EMA alpha = 0.20  (decay = 0.80)
eligibility observations = 20
k_min = 4
global warmup = 300 events
regroup interval = 100 events
minimum merge cosine = 0.0
LoRA rank / alpha = 4 / 8
```

`k_min=4` is a lower bound on the number of agglomerative groups, not a minimum
number of observations and not a minimum group size. A regular regroup can stop
with more than four groups if every remaining group-pair cosine is negative.

## Named historical-target configuration

The historical target name is:

```text
p0_bias_best_cflsplit_a_m005_u10_e50
```

In this repository it maps to `full_final`, which contains:

```text
full route-gradient agglomerative regroup
+ warmup initial grouping
+ rank-4 group LoRA
+ scalar per-user calibration bias
+ holdout-verified local split
   margin=0.005, min users=10, min child events=50
+ mature-user recent-loss refinement
   min observations=20, loss margin=0.01
```

The split and mature refinement are optional post-processing components; they
are not part of the agglomerative merge itself. Current traces show that the
historical verified-split settings often accept no split, while mature
refinement can dominate runtime. For that reason, this repository also exposes
`full_regroup_no_post` and `incremental_split_merge` as explicit ablations.

## Prediction and metric protocols

Two protocols are intentionally kept distinct:

- **Raw SOTA protocol**: `raw_probability >= 0.5`, without threshold search or
  three-step smoothing.
- **SG-Share tuned deployment protocol**: the complete tuned output, including
  its configured online prediction path.

The tables below compare deployed outputs, not a symmetric threshold-only
algorithm benchmark. This favors SG-Share and must be stated whenever the table
is used. Classification F1, precision, and recall are class-macro values. AUC is
computed from continuous probabilities. Cold-start user-macro F1 is computed
per user on first-K events and then averaged; pooled F1 is computed after pooling
all first-K events.

## Full-regroup component-ablation settings

The current code exposes three directly comparable CES variants:

| Variant | Partition update | Verified split | Mature refine |
|---|---|---:|---:|
| `standalone` | full singleton-to-group regroup | on | on |
| `full_regroup_no_post` | full singleton-to-group regroup | off | off |
| `incremental_split_merge` | reuse previous groups; local split/merge | off | off |

This ablation isolates the partition-update mechanism. Both structural variants
disable the separate verified-split and mature-refinement post-processors, so
`full_regroup_no_post` versus `incremental_split_merge` changes only how the
partition is updated. `standalone` remains the complete historical-target
reference. Use all 35,289 CES events and report seeds 42, 43, and 44 separately
or as mean +/- standard deviation; do not substitute short-stream screening
values.

Run the ablation with:

```bash
python process/run_shadow_personal_globem_experiment.py \
  --dataset ces \
  --data data/processed/ces.csv \
  --output results/ces_regroup_ablation \
  --variants standalone,full_regroup_no_post,incremental_split_merge \
  --seeds 42,43,44 \
  --device cpu --torch-threads 24
```

## Data contract

Participant-level CES and GLOBEM data are not committed. Obtain the datasets
from their official providers and prepare canonical streams under the ignored
`data/processed/` directory. See [official data sources](docs/OFFICIAL_DATA_SOURCES.md)
and [data preparation](docs/DATA.md).

The canonical stream format is:

```text
user_id,timestamp,label,<numeric feature columns...>
```

Rows must be chronological and labels must be binary. The recovered CES stream
contains 35,289 events, 218 users, 10,053 positive labels, and 37 model features.
Historical processed streams must be loaded with `--no-scaling` to avoid a
second transformation.

## Main runners

```bash
# Reconstructed framework and baseline matrix
python -m sgshare.reproduce \
  --datasets ces,globem \
  --data-root data/processed \
  --output-root results/reproduction \
  --seeds 42,43,44 \
  --no-scaling

# Raw fixed-0.5 online SOTA suite
python process/run_online_sota_suite.py --help

# Parameter search over signature alpha, eligibility lambda, and k_min
python process/run_sg_share_parameter_search.py --help

# Group-adapter and regroup ablations
python process/run_group_adapter_update_experiment.py --help
python process/run_shadow_personal_globem_experiment.py --help
```

Online SOTA ports and their limits are documented in
[ONLINE_SOTA_REPRODUCTION.md](docs/ONLINE_SOTA_REPRODUCTION.md),
[SOTA_PORTS.md](docs/SOTA_PORTS.md), and
[THIRD_PARTY.md](docs/THIRD_PARTY.md). Do not apply SG-Share-specific smoothing
or tuned decision thresholds to a SOTA method unless that altered protocol is
reported separately.

## Outputs

The generic experiment path writes:

- `metrics.json`: full-stream, post-warmup, and first-K metrics;
- `events.csv`: prequential predictions emitted before each update;
- `cold_start.csv`: user-macro and pooled first-K metrics;
- `groups.csv`: regroup, split, reassignment, churn, and adapter diagnostics;
- `config.yaml`: resolved configuration.

Specialized audit runners may additionally write `summary.csv`,
`summary_mean_std.csv`, `cold_start_configured.csv`, `cold_start_raw.csv`,
`diagnostics.json`, and `config.json`.

## Repository boundary

This repository does not contain participant-level raw/processed datasets,
generated event logs, checkpoints, or copies of third-party repositories.
Third-party audits can be restored at pinned commits with:

```bash
bash scripts/fetch_third_party.sh
```

See [THIRD_PARTY.md](docs/THIRD_PARTY.md) for upstream repositories, pinned
commits, and the distinction between source-grounded ports and mechanism
reproductions.
