# SG-Share: Auditable Online Group Adaptation

This repository is a clean-room reconstruction and audit package for SG-Share,
an online group-adaptation system for passive-sensing mental-health streams. It
contains the stream preparation code, the current SG-Share learner, online and
offline comparison runners, grouping/component ablations, and provenance
records.

The historical experiment repository was not recovered byte-for-byte. Results
and claims are therefore separated into:

- **Recovered tuned-system results**: values recovered from experiment outputs
  and execution records.
- **Current reconstruction results**: values generated by the `sgshare/`
  implementation in this repository.
- **Expected manuscript values**: reference values stored under `expected/`;
  these are not silently presented as newly reproduced results.

Read [the provenance record](docs/PROVENANCE.md),
[reproduction status](docs/REPRODUCTION_STATUS.md), and
[SOTA audit](docs/SOTA_FAITHFULNESS_AUDIT.md) before interpreting numerical
comparisons.

## Implemented online protocol

All SG-Share runs are prequential: each event is predicted first, its label is
then revealed, and only past and current labeled feedback may be used for an
update.

The implemented group path is:

1. A temporary rank-4 LoRA adapter serves each user before group eligibility.
2. The classification-loss gradient on `route_w` updates a per-user EMA
   signature.
3. At a regroup boundary, eligible signatures are standardized and projected to
   at most eight principal coordinates.
4. Full regrouping starts from user singletons and repeatedly merges the pair of
   group centroids with maximum cosine similarity. It stops at `k_min` groups or
   when the best similarity is negative.
5. Stable group identifiers are matched to the new partition. Eligible users
   train and predict through their assigned group adapter; in the default
   `standalone` mode, their temporary personal adapter is not updated afterward.

### Dataset-specific classification-tuned configuration

The main experiment runners resolve the dataset YAML and then apply the
classification-tuned point in `process/run_table3_experiments.py`. The resulting
settings are:

| Parameter | CES | GLOBEM |
|---|---:|---:|
| TinyTFT hidden dimension / depth / heads | 32 / 2 / 4 | 16 / 1 / 2 |
| LoRA rank / alpha | 4 / 8 | 4 / 8 |
| Backbone learning rate | 0.0002 | 0.0003 |
| Group-adapter learning rate | 0.007 | 0.005 |
| Focal gamma / alpha | 2.0 / 0.75 | 2.0 / 0.75 |
| Positive-class loss weight | 5.0 | 5.0 |
| Route-gradient EMA alpha / decay | 0.20 / 0.80 | 0.20 / 0.80 |
| Normalize route gradient before EMA | no | no |
| Eligibility observations (`lambda`) | 20 | 2 |
| Individual warmup observations | 20 | 2 |
| Initial grouping boundary | event 300 | event 120 |
| Periodic regroup interval | 100 events | 120 events |
| Agglomerative lower bound (`k_min`) | 4 | 4 |
| Minimum merge cosine | 0.0 | 0.0 |
| Warmup signature count | 10 | 5 |
| Smoothing window | 5 | 3 |
| Threshold mode / default | in-window / 0.5 | in-window / 0.5 |
| Threshold history / refresh interval | 1000 / 100 | 500 / 50 |
| User-posrate threshold correction | off | on, alpha 0.09 |
| Cold-safe mixing eta | 0.50 | 0.25 |
| Global / personal / group cold prior | 0.30 / 0.50 / 0.20 | 0.05 / 0.25 / 0.70 |
| Configured learner first-K values | 5, 10, 20, 50 | 5, 10 |
| `run_table3_experiments.py` summary K values | 5, 10, 20 | 5, 10 |

The base YAML stores a route-gradient decay of `0.95` for both datasets and a
GLOBEM minimum-observation value of `5`. These are initialization defaults, not
the classification-tuned experiment values. `_configured(...)` overrides them
with `ECAP_POINTS`: `(alpha=0.20, lambda=20, k_min=4)` for CES and
`(alpha=0.20, lambda=2, k_min=4)` for GLOBEM. Every run writes its fully resolved
configuration to `config.json`; that file is authoritative for a numerical
result.

The following `full_final` settings are shared by CES and GLOBEM:

| Component | Resolved setting |
|---|---|
| Optimizer regularization | weight decay `1e-4` |
| Backbone online update | LR scale `0.3`; route-gradient clip norm `1.0` |
| Warmup fallback | minimum samples `5`, fallback `1`; minimum eligible users `10`, fallback `2` |
| Warmup group range | minimum `2`, maximum `12`; force initial acceptance on |
| Prototype initialization | enabled; minimum samples `3`; blend alpha `0.35` |
| Per-user bias | enabled; LR `0.005`; L2 `0.001`; clip `2.0`; group-mean initialization weight `0.5` |
| Verified split | enabled; loss margin `0.005`; minimum users `10`; minimum events `50`; minimum holdout users `5`; maximum groups `8` |
| Split guards | positive-rate tolerance `0.10`; cohesion tolerance `0.05`; no recent-buffer fallback |
| Mature-user refinement | enabled at `20` observations; minimum buffer `5`; loss margin `0.01`; evaluate every `10` events |
| Cold-safe mixing horizon | first `20` observations |

Thus, `lambda` is dataset-specific (`20` for CES and `2` for GLOBEM), while
the mature-refinement threshold remains `20` on both datasets. These parameters
must not be treated as the same gate.

`k_min=4` is a lower bound on the number of agglomerative groups, not a minimum
number of observations and not a minimum group size. A regular regroup can stop
with more than four groups if every remaining group-pair cosine is negative.

## Named deployment presets

The recovered classification-tuned and cold-safe parameter points now have a
single executable interface:

```bash
python process/run_sg_share_named_preset.py \
  --dataset ces --preset classification_tuned \
  --data data/processed/ces.csv --output results/ces_classification_tuned

python process/run_sg_share_named_preset.py \
  --dataset globem --preset cold_safe \
  --data data/processed/globem.csv --output results/globem_cold_safe
```

The four exact dataset/preset combinations, their eligibility semantics, and
their differences from the previous GitHub runner interface are documented in
[Named presets](docs/NAMED_PRESETS.md). Every run stores `preset.json` and the
complete resolved `config.yaml`.

Run all online SOTA scopes plus both named SG-Share presets without touching
the processed datasets:

```bash
bash scripts/run_named_reproduction.sh data/processed results/named_reproduction
```

In this repository it maps to `full_final`, which contains:

```text
full route-gradient agglomerative regroup
+ warmup initial grouping
+ rank-4 group LoRA
+ scalar per-user calibration bias
+ holdout-verified local split
   margin=0.005, min users=10, min child events=50
+ mature-user recent-loss refinement
   min observations=20, loss margin=0.01
```

The split and mature refinement are optional post-processing components; they
are not part of the agglomerative merge itself. They remain unchanged in the
regroup on/off comparison below so that the ablation tests the complete online
regroup module rather than replacing it with another partition algorithm.

## Prediction and metric protocols

Two protocols are intentionally kept distinct:

- **Raw SOTA protocol**: `raw_probability >= 0.5`, without threshold search or
  three-step smoothing.
- **SG-Share tuned deployment protocol**: the complete tuned output, including
  its configured online prediction path.

The tables below compare deployed outputs, not a symmetric threshold-only
algorithm benchmark. This favors SG-Share and must be stated whenever the table
is used. Classification F1, precision, and recall are class-macro values. AUC is
computed from continuous probabilities. Cold-start user-macro F1 is computed
per user on first-K events and then averaged; pooled F1 is computed after pooling
all first-K events.

## Periodic-regroup component-ablation settings

The regroup ablation is a strict on/off comparison, not a comparison with a
split/merge replacement:

| Variant | Initial grouping at warmup | Periodic regroup after warmup | Other full-final components |
|---|---:|---:|---|
| `regroup_on` | on | on, at the dataset-specific interval | unchanged |
| `regroup_off` | on | off; freeze the initial partition | unchanged |

The dataset-specific schedules are:

| Dataset | Processed stream | Events | Initial grouping | Regroup-on interval |
|---|---|---:|---:|---:|
| CES | `data/processed/ces.csv` | 35,289 | event 300 | 100 events |
| GLOBEM | `data/processed/globem.csv` | 8,225 | event 120 | 120 events |

Within each dataset, both variants construct the same route-gradient initial
partition and retain the same TinyTFT backbone, group LoRA, eligibility rule,
per-user bias, verified-split settings, mature-refinement settings, and
prediction protocol. The only switch is `periodic_regroup_enabled`.
Consequently, the comparison measures whether repeatedly refreshing
user-to-group assignments is useful beyond establishing the initial
group-sharing structure. In the off arm, group adapters continue to receive
online updates, but group membership remains fixed after the initial boundary.
Use the complete processed streams; do not substitute short-stream screening
values.

Run the ablation with:

```bash
python process/run_shadow_personal_globem_experiment.py \
  --dataset ces \
  --data data/processed/ces.csv \
  --output results/ces_regroup_ablation \
  --variants regroup_on,regroup_off \
  --seeds 42,43,44 \
  --device cpu --torch-threads 24

python process/run_shadow_personal_globem_experiment.py \
  --dataset globem \
  --data data/processed/globem.csv \
  --output results/globem_regroup_ablation \
  --variants regroup_on,regroup_off \
  --seeds 42,43,44 \
  --device cuda --torch-threads 12
```

## Data contract

Participant-level CES and GLOBEM data are not committed. Obtain the datasets
from their official providers and prepare canonical streams under the ignored
`data/processed/` directory. See [official data sources](docs/OFFICIAL_DATA_SOURCES.md)
and [data preparation](docs/DATA.md).

The canonical stream format is:

```text
user_id,timestamp,label,<numeric feature columns...>
```

Rows must be chronological and labels must be binary. The recovered CES stream
contains 35,289 events, 218 users, 10,053 positive labels, and 37 model features.
Historical processed streams must be loaded with `--no-scaling` to avoid a
second transformation.

```bash
# Reconstructed framework and baseline matrix
python -m sgshare.reproduce \
  --datasets ces,globem \
  --data-root data/processed \
  --output-root results/reproduction \
  --seeds 42,43,44 \

python process/run_sg_share_parameter_search.py --help

# Group-adapter and regroup ablations
python process/run_group_adapter_update_experiment.py --help
python process/run_shadow_personal_globem_experiment.py --help
```

Online SOTA ports and their limits are documented in
[ONLINE_SOTA_REPRODUCTION.md](docs/ONLINE_SOTA_REPRODUCTION.md),
[SOTA_PORTS.md](docs/SOTA_PORTS.md), and
[THIRD_PARTY.md](docs/THIRD_PARTY.md). Do not apply SG-Share-specific smoothing
or tuned decision thresholds to a SOTA method unless that altered protocol is
reported separately.

## Outputs

The generic experiment path writes:

- `metrics.json`: full-stream, post-warmup, and first-K metrics;
- `events.csv`: prequential predictions emitted before each update;
- `cold_start.csv`: user-macro and pooled first-K metrics;
- `groups.csv`: regroup, split, reassignment, churn, and adapter diagnostics;
- `config.yaml`: resolved configuration.

Specialized audit runners may additionally write `summary.csv`,
`summary_mean_std.csv`, `cold_start_configured.csv`, `cold_start_raw.csv`,
`diagnostics.json`, and `config.json`.
